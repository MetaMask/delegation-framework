# X1 — Compact fixed-schema order encoding

## Purpose

Replace `abi.encode(Delegation[])` permission contexts with a fixed binary schema (`CompactOrderCodec`, magic `0xC0DEC001`) for single-delegation limit-order hot paths. `X1CompactOrderDelegationManager` decodes compact contexts; standard ABI contexts still work for differential testing.

## Semantic delta

- **Retained:** Same EIP-712 delegation hash, hook phases, `executeFromExecutor` forwarding, disable/enable semantics.
- **Lost:** Multi-delegation chains in compact mode; dynamic ABI extensibility; wallet/indexer compatibility without compact encoder.

## Benchmark

```bash
forge test --isolate -vv --match-contract X1CompactOrderBenchmark
```

Environment: `foundry.toml` default (`solc 0.8.23`, `evm_version = london`, `optimizer = true`).

Scenario: 1-exec batch, combined enforcer, EIP-7702 EOA delegator.

## Code size

Experiment-only contracts under `src/experiments/X1/`; canonical `DelegationManager.sol` unchanged.

## Security findings

- Compact decoder is strict; malformed/trailing bytes revert (`CompactOrderTruncated`).
- Fixed schema must be versioned off-chain; no on-chain fallback for unknown caveat layouts.
- Encoder/decoder are new attack surface; no auth bypass found in isolated redemption tests.

## Verdict

**Drop for general ERC-7710 compatibility.** Keep as an optional transport encoding when order shape is fixed (single root delegation, known caveat count) and relayers control encoding. Calldata savings (~25%) exceed exec savings (~10%) — best paired with batch relay / L2 posting cost sensitivity.
