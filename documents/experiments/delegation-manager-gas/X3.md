# X3 — First-fill signature activation cache + epoch invalidation

## Purpose

After one successful signature validation per `(delegator, delegationHash, epoch)`, skip ECDSA/ERC-1271 on subsequent fills. Epoch bumps on `disableDelegation` or `bumpDelegatorEpoch()`.

## Semantic delta

- **Retained:** Disabled delegations, hook phases, authority checks, `executeFromExecutor` path.
- **Changed:** Repeat fills skip on-chain signature verification if activation bit is set for current epoch.
- **Risk:** Smart-account **ERC-1271 policy changes** after first fill are not observed until epoch bump.

## Benchmark

```bash
forge test --isolate -vv --match-contract X3ActivationCacheBenchmark
```

Scenario: 1-exec batch, combined enforcer (limit 10), EIP-7702 EOA.

| Variant | Exec gas | Est. tx gas |
| --- | ---: | ---: |
| Canonical manager (every fill validates sig) | 154,498 | 185,770 |
| X3 first fill (validate + cache write) | 178,216 | 209,476 |
| X3 second fill (cache hit) | 114,886 | 146,146 |
| **Warm cache vs canonical** | **−39,612 (−25.6%)** | **−39,624 (−21.3%)** |
| **Warm cache vs X3 first fill** | **−63,330 (−35.5%)** | **−63,330 (−30.2%)** |

First fill is **more expensive** than canonical due to cache write; break-even requires ≥ 2 fills per epoch per delegation hash.

## ERC-1271 policy-change risks

| Scenario | Behavior |
| --- | --- |
| EOA delegator | Lower risk; key rotation invalidates off-chain signatures anyway. |
| ERC-1271 wallet changes validator | **High risk** — cached activation accepts stale policy until epoch bump. |
| `disableDelegation` | Bumps epoch → new activation key required. |
| Maker `bumpDelegatorEpoch()` | Bulk-invalidates all activation cache entries for delegator. |

## Security findings

- Disqualifying for permissionless/public mempool use with contract delegators.
- Acceptable only with explicit maker opt-in + short epoch TTL + off-chain monitoring — still weaker than canonical manager.

## Verdict

**Reject for production default.** Gas upside on warm fills (~26%) does not justify ERC-1271 policy drift. If revived: limit to EOA-only delegators, require short epochs, and never combine with `ANY_DELEGATE` public fillers without extra guards.
