# X2 — EIP-1153 transient hook/balance coordination

## Purpose

Compare ERC-20 before/after hook coordination using persistent storage (`PersistentERC20HookCoordinator`) vs EIP-1153 transient slots (`TransientERC20HookCoordinator` + `TransientStorageLib`).

## Semantic delta

- **Retained (persistent control):** Same balance-delta semantics as `ERC20BalanceChangeEnforcer` pattern (73-byte terms).
- **Transient variant:** Identical hook API; balance snapshot lives in transient storage cleared at tx end.

## Benchmark

Default profile (portable control only):

```bash
forge test --isolate -vv --match-contract X2PersistentHookBenchmark
```

| Variant | Exec gas | Calldata bytes | Est. tx gas |
| --- | ---: | ---: | ---: |
| Persistent coordinator (control) | 140,449 | 1,412 | 170,577 |

### Transient variant — **SKIPPED on default config**

| Blocker | Detail |
| --- | --- |
| `evm_version` | Default `foundry.toml` uses `london` (no EIP-1153). |
| `solc` | Project pins `0.8.23`; `tload`/`tstore` builtins require **≥ 0.8.24** with Cancun. |
| Transient contracts | Excluded from default compile via `foundry.toml` `skip`. |

To attempt transient benchmarks after installing `solc 0.8.24+`:

```bash
# Requires foundry profile with evm_version=cancun and solc>=0.8.24 aligned project-wide
FOUNDRY_PROFILE=cancun forge test --isolate -vv --match-contract X2TransientHookBenchmark
```

Expected direction: transient path avoids persistent `SSTORE`/`SLOAD` on coordinator mappings (~2 warm storage ops per redemption on control).

## Security findings

- Persistent control inherits shared-state caveats documented on `ERC20BalanceChangeEnforcer`.
- Transient storage is **tx-scoped** — safer against cross-tx leakage but **not available on pre-Cancun chains**.
- Reentrancy: coordinator lock is tx-local (persistent) or transient; same reentrancy assumptions as canonical enforcer hooks.

## Verdict

**Skip transient until Cancun + solc ≥ 0.8.24 in CI.** Persistent control is the portable baseline. Re-evaluate transient on L2/Cancun deployments once measured; likely **keep as chain-specific optimization**, not default framework behavior.
